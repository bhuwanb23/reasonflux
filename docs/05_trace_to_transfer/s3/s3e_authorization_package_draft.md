## 4. Analysis and reporting lock

Before any run authorization, the operator must freeze and verify:

1. Exact source and held-out manifests, cell membership, context IDs, outcomes generated by the observable world, and role-disjointness checks.
2. R0–R4 and I0 code/config hashes, source contrast coverage, and the common source manifest for every arm.
3. One prediction record per arm/context or an explicit missing record; predictions logged before observed effects are attached.
4. All-context and per-cell denominators, exact correct/wrong/abstain/invalid/missing counts, coverage, and cell eligibility reasons.
5. Primary contrast exactly `Accuracy(I0) - Accuracy(R4)`; do not round before applying the sign decision. No composite score, post-hoc subset, or abstention exclusion.
6. R1's positive-trace agreement is implied by validated effect values (`SUCCESS` only for positive traces); any changed source schema requires a new package version.
7. No held-out outcome may update, refit, or select the frozen R4/I0 version. Any post-exposure change invalidates the held-out suite for that version and requires a fresh prospective version/suite.
8. Stop rules and N-PASS/N-FAIL/N-BLOCKED reporting exactly as in `s3_plan.md`.

The current scorer reports per-arm/per-cell accuracy and counts but does not calculate `Delta_N`; the run analysis must use the frozen subtraction above or add a separately reviewed deterministic calculator before exposure. The calculation must be recorded in the analysis script/report before labels are exposed.
