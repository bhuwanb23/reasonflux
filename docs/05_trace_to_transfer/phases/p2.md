# P2 — Formal skill object

**Status:** COMPLETE for documentation/design scope as of 2026-11-03. Completion does not authorize code, experiments, benchmarks, ARC runs, split assignment, or access to restricted outcomes.

## Objective

Define an invariant skill as a versioned object with evidence, parameter binding, applicability, predicted effects, termination/fallback, provenance, and an auditable lifecycle—without silently relabeling traces, macros, options, or candidate hypotheses as skills.

## Inputs and dependencies

P1 disposition: no-go on the standalone novelty claim; owner-selected comparative ARC-specific research direction. P2 formalizes the object needed to articulate that question; it does not claim the object is novel or experimentally validated. Dependencies follow the T2T master plan; existing project/data restrictions remain controlling.

## Work sequence and outcomes

1. **P2.1 — Schema:** complete. Specified candidate vs executable skill records, fields/types, explicit unknowns, immutable IDs/content digests, representation-version pins, and append-only status events.
2. **P2.2 — Invariant versus replay:** complete. Defined raw replay, strong parameterized/compressed replay, and the operational semantic delta for an invariant skill; specified when Claim N is unidentifiable or unsupported.
3. **P2.3 — Evidence and lifecycle:** complete. Specified evidence references/snapshots, prediction/outcome separation, typed counterexamples, candidate/skill lifecycle states, quarantine, successor versions, promotion semantics, and retirement.

## Completion and unresolved decisions

The design contract is versioned `T2T-SkillObject-v1.0.0-draft`. The JSON Schema passed syntax/meta-schema checking; both applicability examples and the embedded pre-outcome prediction record conform to its shape; this is documentation QA only. The contract and examples are internally reconciled across P2.1–P2.3.

Still open by design: ARC state/object/action/effect ontology; exact relation/predicate DSL; recurrence/support/validation/promotion thresholds; calibration; matched-state/counterfactual construction; exact runtime resource caps; and future source manifests. No threshold, split, candidate population, or implementation behavior is silently chosen by P2. P2 completion does not make a candidate eligible, validated, active, or novel.

**Boundary:** no code/implementation, experiments, benchmarks, ARC runs, split assignment, or restricted-outcome access are authorized by P2. No candidate has been formed, promoted, or executed.
