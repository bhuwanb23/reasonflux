# P2 — Formal skill object

**Status:** design/documentation work package only. Completion does not authorize code, experiments, benchmarks, ARC runs, split assignment, or access to restricted outcomes.

## Objective

Define an invariant skill as a versioned object with evidence, parameter binding, applicability and predicted effects.

## Inputs and dependencies

Draft schema in ../formal_skill_object.md.
Dependencies follow the T2T master plan; existing project restrictions remain controlling.

## Work sequence

1. **P2.1 — Schema:** Specify fields, data types, required/unknown values, immutable IDs and version changes.
2. **P2.2 — Invariant versus replay:** Define operationally what semantic relation exceeds a stored or parameterized trace.
3. **P2.3 — Evidence and lifecycle:** Define evidence links, candidate statuses, promotion, quarantine, revision and retirement.

## Deliverable

Implementable schema contract plus invariants and interoperability fixtures.

## Acceptance and boundary

Review the deliverable for internal consistency, version it, and record unresolved questions. **Boundary:** No silent relabeling of traces, macros, options or candidate objects as invariant skills.
