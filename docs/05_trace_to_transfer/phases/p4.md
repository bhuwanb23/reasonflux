# P4 — Counterexample boundary algorithm

**Status:** design/documentation work package only. Completion does not authorize code, experiments, benchmarks, ARC runs, split assignment, or access to restricted outcomes.

## Objective

Specify candidate extraction, contradiction handling, boundary refinement and runtime abstention.

## Inputs and dependencies

Algorithm sketch in ../counterexample_boundary_algorithm.md.
Dependencies follow the T2T master plan; existing project restrictions remain controlling.

## Work sequence

1. **P4.1 — Candidate generation:** Specify state abstraction, trace alignment, motif proposal and source support accounting.
2. **P4.2 — Counterexample taxonomy:** Separate genuine scope contradiction from execution error, observation uncertainty, missing condition and unresolved cases.
3. **P4.3 — Scope refinement:** Define how evidence can add/remove conditions, split versions, lower coverage or reject a candidate.
4. **P4.4 — Fallback:** Define abstain, safe fallback, step limit, mismatch stop and event logging.

## Deliverable

Deterministic algorithm, taxonomy, data-use rules and failure/fallback semantics.

## Acceptance and boundary

Review the deliverable for internal consistency, version it, and record unresolved questions. **Boundary:** Do not use a target result to refine the same version then count it as held-out validation.
