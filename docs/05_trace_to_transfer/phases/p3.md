# P3 — Claim N and fair replay controls

**Status:** design/documentation work package only. Completion does not authorize code, experiments, benchmarks, ARC runs, split assignment, or access to restricted outcomes.

## Objective

Test conceptually whether invariant semantics add value beyond replay and parameterized/compressed traces.

## Inputs and dependencies

Claim N draft in ../claim_n_specification.md.
Dependencies follow the T2T master plan; existing project restrictions remain controlling.

## Work sequence

1. **P3.1 — Raw replay:** Define the fixed trace/script control and its invocation assumptions.
2. **P3.2 — Strong replay:** Design a competent compressed/parameterized trace baseline without learned cross-context invariant boundaries.
3. **P3.3 — Isolation and budget matching:** Set matched input data, memory, context, compute, action, model and evaluation conditions.

## Deliverable

Fair baseline definitions, budget matching rules, ablations, estimands and falsifiers.

## Acceptance and boundary

Review the deliverable for internal consistency, version it, and record unresolved questions. **Boundary:** Raw replay alone is insufficient; strong replay is required. No outcome-based baseline tuning.
