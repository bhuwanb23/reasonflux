# P6.2 — Event schema

**Parent:** [T2T-P6](../phases/p6.md)  
**Status:** COMPLETE for documentation/design scope, 2026-11-04. At P6.2 completion no validator existed; a separate, narrowly authorized Step 1 later created a machine-readable local schema and validator, without resolving P2 production identity/canonicalization or authorizing real-data use.

## Deliverable

[`T2T-EventSchema-v1.0.0-draft`](../p6/event_schema_v1.md), specifying an immutable event envelope, ordering and correction semantics, payload requirements for observations, applicability, predictions, actions, transitions, candidate/skill versions, lifecycle, P4 triage, fallback, failures, costs, and the restricted evaluator-outcome boundary.

## Result

P2 records remain authoritative and are referenced rather than extended. Prediction, action, observation/transition, effect assessment and evaluator outcome remain separate. A pre-action prediction must precede dispatch by both journal order and P2-required timestamp ordering. Unknown is distinct from absent, known false and `NOT_APPLICABLE`; costs preserve missingness and units. P4 fine-grained triage remains in its sidecar and maps to the existing P2 enum. Corrections append and never overwrite prior events.

## Unresolved and boundary

Event IDs, canonical serialization/digest profile, exact JSON Schema dialect, stream/clock implementation, storage/retention, resource units, privacy and physical restricted-store boundaries remain open. This is a schema proposal, not a deployed schema service or authorization.
