# P3.1 — Raw replay

**Parent:** [T2T-P3](../phases/p3.md)  
**Status:** COMPLETE for documentation/design scope; not a readiness gate or authorization.

## Deliverable

R0 definition in the [P3 fair replay contract](../p3/fair_replay_controls_v1.md#3-arm-definitions).

## Control definition

R0 retrieves a source trace through the common frozen retrieval interface, then replays its exact ordered actions and literal recorded arguments under the recorded source-context assumptions. It does not compress, rebind, repair, retry around a mismatch, branch on a learned cross-context relation, or infer a new applicability region.

Use only recorded pre-action checks, exactly as logged. For prediction endpoints, emit only a recorded next-effect expectation aligned to the exact selected trace/action; otherwise abstain. If a required source-context check fails, an observation/action is missing or unsupported, an expected transition mismatches, or applicability is ambiguous, stop and return the frozen `ABSTAIN/ERROR` path. If the trace has no pre-action checks, document its fixed-state assumption; do not imply robust execution. Keep every attempt and cost in the log.

## Fairness role and limits

The same source corpus, query/retrieval features and budget, observation/context interface, action interface, evaluator, and resource opportunities are used for other arms. R0 is a reference for fixed-sequence playback and engineering gains; it is not a sufficient comparator for Claim N when the proposed method has retrieval, parameters, or compression. The required Claim N comparator is R1 (P3.2).

## Unresolved for a future authorized protocol

Source manifest, exact context keys/checks, missing-check behavior, retrieval implementation, log schema, evaluator/context cohort, numerical caps and assignment rules remain unset. No trace was retrieved or replayed in P3; no code or test was run.
