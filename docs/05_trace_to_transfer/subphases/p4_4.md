## Deliverable

Runtime state machine and fail-closed behavior in the [P4 boundary contract](../p4/boundary_algorithm_v1.md#6-p44--runtime-applicability-fallback-and-logging-state-machine), with synthetic mismatch cases in the [decision fixtures](../p4/decision_fixtures.md).

## Result

Invocation requires separate authorization, `ACTIVE` lifecycle status, compatible pinned versions, known runtime-critical units/limits, uniquely bound parameters, and all required applicability predicates `TRUE`. `UNKNOWN` abstains; `FALSE` rejects the local invocation. The PredictionRecord is frozen before any action. A mismatch, invalid action, failed postcondition, or exhausted limit stops the skill before the next action and appends all event/cost records.

Fallback is only the P2-declared path. Without a separate authorized and budgeted policy, terminate with abstain/no-op/abort. Safe-policy or deopt fallback must independently pass its own applicability and budget checks; no hidden retries or uncharged actions. Unknown action/step/time/compute limits block invocation.

## Unresolved and boundary

Numerical caps, units/enforcement, authorized fallback inventory, recovery budget, and runtime approval remain unset. The state machine is design only; no skill was invoked, no fallback run, and no failure test executed in P4.
