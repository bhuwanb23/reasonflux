# P2.1 — Schema

**Parent:** [T2T-P2](../phases/p2.md)  
**Status:** COMPLETE for documentation/design scope; not a readiness gate or authorization.

## Deliverable

The versioned [formal skill object contract](../formal_skill_object.md) and [JSON Schema v1](../p2/schema_v1.json).

## Result

Defined distinct record types for `CandidateVersion`, `SkillVersion`, `EvidenceSnapshot`, `LifecycleEvent`, `PromotionDecision`, `ApplicabilityResult`, `EffectAssessment`, and `CounterexampleRecord`. A candidate is non-executable; a skill version adds policy, parameter binding, applicability, effect prediction, termination and fallback. Lifecycle status is derived from an append-only event stream, never stored as mutable semantic content.

IDs and hash boundaries distinguish lineage identity, immutable semantic versions, evidence snapshots, prediction records, and decision events. Representation/normalizer/relation-language versions are pinned. A `PredictionRecord` is separate from later `EffectAssessment` and requires all applicability predicates to be true. Unknown values use explicit tagged unions; no `null`, false, zero, or empty list is a silent unknown. The JSON Schema rejects unrecognized fields in v1; extensions require a new schema version.

## QA and limits

JSON parses; Draft 2020-12 meta-schema checking passes; both applicability records and the embedded PredictionRecord conform to the declared shapes. This checks documentation/schema structure only. Hash recomputation, reference resolution, data-access policy, and legal transition-sequence checking are stated semantic validators for future authorized work, not implemented here.

No state/action/effect ontology, relation DSL, numeric threshold, or runnable policy was chosen. No implementation or execution was performed or authorized.
