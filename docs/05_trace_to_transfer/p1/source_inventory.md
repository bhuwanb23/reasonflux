# P1.1 — Source Inventory and Review Notes

**Snapshot date:** 2026-11-03. Links point to primary sources wherever available. Summaries below are limited to the accessible paper text/abstract and should be checked against full methods, supplements, code and later versions before a final novelty statement.

## A. Directly overlapping agent-skill learning and evolution

| Work | Primary source / status | Mechanism relevant to T2T | Review implication |
|---|---|---|---|
| **Skill-Pro: Learning Reusable Skills from Experience via Non-Parametric PPO for LLM Agents** (Mi et al., ICML 2026 Spotlight) | [arXiv v3](https://arxiv.org/html/2602.01869v3) · [official code](https://github.com/Miracle1207/ProcMEM) | Skills have activation, execution and termination conditions. Trajectory-derived semantic gradients refine them; a PPO Gate verifies candidate skills; score-based maintenance prunes the pool. | Direct prior art for skills learned from experience with explicit applicability and iterative refinement. “Add conditions and validate a skill” cannot be the wedge. Need compare whether its gate learns a cross-context invariant boundary or evaluates skill quality through reward trajectories. |
| **Skill-DisCo: Distilling and Compiling Agent Traces into Reusable Procedural Skills** (Guo et al., Findings EMNLP 2026) | [ACL Anthology](https://aclanthology.org/2026.findings-emnlp.2260/) · [PDF](https://aclanthology.org/2026.findings-emnlp.2260.pdf) | Normalizes successful traces to executable programs, segments and clusters parameterized control-flow fragments, formalizes reusable skills as parameterized finite-state-machine subgraphs matched across successful traces, then compiles callable, executable, verifiable skills. | Close to the proposed cross-trace invariant object: repeated transition/control-flow structure is already formalized as a reusable skill. T2T must distinguish its effect relation and boundary-update signal from PFSM subgraph abstraction, not simply claim that an invariant is extracted across traces. The reviewed method centers on successful traces and compilation; confirm full treatment of negative evidence in the remaining appendix/code review. |
| **StateSkill-Agent: An Effective and Efficient Embodied Agent via State-conditioned Skill** (Wei et al., arXiv v1, 2026-10-10) | [arXiv v1 HTML](https://arxiv.org/html/2610.14601v1) | Represents embodied skills as finite-state machines over task-progress states, transitions, and state-conditioned guidance/action priors. StateSkill-Evolve retrospectively uses successful and failed trajectories to revise state distinctions, transition gates, guidance, and action priors. | Strong cross-domain overlap with state-conditioned reusable structure and failure-informed skill evolution. Not ARC and not formal invariant-boundary learning; nevertheless T2T cannot claim FSM/state-conditioned skills, abstracting shared trajectory behavior, or failure-based skill revision in general. |
| **SkillComposer: Learning to Evolve Agent Skills for Specification and Generalization** (Zhang et al., 2026) | [arXiv v1](https://arxiv.org/html/2606.06079v1) | Decomposes skill evolution into create, improve and merge; supports offline, online and hybrid libraries; explicitly treats specificity/generalization tension. | Direct overlap with skill lifecycle, refinement, merging and generalization. A lifecycle framing is not distinctive. The proposed method must isolate a concrete evidence-driven boundary rule and comparator. |
| **ReSkill: Reconciling Skill Creation with Policy Optimization in Agentic RL** (He et al., 2026, arXiv v2) | [arXiv v2 HTML](https://arxiv.org/html/2606.01619v2) · [Amazon Science code](https://github.com/amazon-science/reskill) | Within-group rollouts compare competing skill versions under policy optimization; an assertion-driven creator diagnoses failures and proposes conditional, trigger-based revisions; Thompson sampling selects skill versions as policy changes. | Directly occupies conditional skill loading, failure diagnosis, trigger refinement, and controlled comparison of versions. Different objective/training regime than T2T, but contradicts claims that failure-informed trigger/scope revision is generally new. |
| **Defense-as-Skill: Evolving Runtime Guard Skill for Skill-Augmented Agents** (Yang et al., arXiv v4, 2026-10-27; NeurIPS 2026 per arXiv record) | [arXiv v4 HTML](https://arxiv.org/html/2609.01487v4) · [project/code](https://github.com/yxf203/defense-as-skill) | Packages a task-conditioned runtime guard as a reusable skill; MCTS edits the guard from concrete rollout feedback and checks proposed actions against task boundaries, across two agent harnesses. | Adjacent rather than a direct invariant learner: safety guard policy, not a learned cross-context effect invariant. Still establishes evolving guard-skills, boundary-conditioned action checks, and rollout-feedback revision as a developed design pattern. |
| **Trace2Skill: Distill Trajectory-Local Lessons into Transferable Agent Skills** (Ni et al., 2026) | [arXiv v5 PDF](https://arxiv.org/pdf/2603.25158) · [official repository](https://github.com/Qwen-Applications/Trace2Skill) | Collects success/failure trajectories; parallel error/success analysts propose patches; hierarchical consolidation yields a portable skill directory. Reports held-out and cross-model/OOD transfer. | Direct overlap with trace-derived portable lessons, failure-derived corrections and cross-context transfer. The distinction cannot be “counterexamples help” generally; need a specific formal scope-update mechanism and fair incremental comparator. |
| **Break It Down, Pass It On: Cross-Task Skill Transfer in LLM Agents** (Feng et al., 2026) | [arXiv v2](https://arxiv.org/html/2608.20274) | Controlled study of task-level vs subtask-level induction and text vs code formats; studies positive/negative transfer and skill specificity/abstractness. | Directly addresses how granularity and format affect cross-task transfer and harm. T2T needs a different mechanistic variable, not just improved transfer or less negative transfer. |
| **Not All Skills Help: Measuring and Repairing Agent Knowledge (ASSAY)** (Wang et al., 2026) | [arXiv HTML](https://arxiv.org/html/2606.15390) | Randomized masking estimates per-skill causal utility across development tasks; reorganizes/splits/retire skills and predicts per-task masking to suppress harmful skills. | Direct prior art for conditional skill utility, per-task applicability, harmful transfer and evidence-based selection. T2T cannot claim generic scope selection or causal skill-effect audit as novel. It may differ by deriving observable symbolic/effect boundaries from counterexamples, but that needs exact comparison. |
| **Towards Strategy-Level RSI for Skill-Augmented Agents: Learning When to Reuse Skills from Execution Feedback (SkillApt)** (Guo et al., arXiv v2, 2026-10-08) | [arXiv v2 HTML](https://arxiv.org/html/2609.26863v2) · [version record](https://arxiv.org/abs/2609.26863) · [code](https://github.com/guoshaung/SkillApt) | For a fixed candidate textual skill, constructs matched WITH/WITHOUT runs on the same task state under fixed model/prompt/evaluator; stores outcome-derived marginal-utility labels, then aggregates evidence from similar states to choose LOAD/ABSTAIN. Revises the external activation policy, not the procedure. The v2 primary experiment uses 20 skills, 12 evidence states per skill, and 160 held-out states; reported success reaches 91.3% versus 81.9% cold-start and matches the strong zero-shot controller at 91.3%, while activating on 26.3% vs 98.8% and reducing selected tokens. | **Closest published method-level overlap located.** The paper explicitly frames applicability as state-conditioned use/abstain and evidence-accumulating boundary revision. Its supervision is paired outcome/cost utility, not a cross-context structural action/effect invariant or prospective dynamics-mismatch taxonomy; experiments concern textual skills in tool/task domains, not ARC-AGI-3. The reported gain is selectivity/cost versus near-always-load, not accuracy superiority over the strongest controller. T2T must test structural evidence's incremental value against this type of controller, not claim boundary learning or selective use as novel. |
| **Skill or Skip? Learning Selective Skill Invocation in Agentic Tasks via Dual-Granularity Preference Learning (SelSkill)** (Chen et al., 2026, arXiv v2) | [arXiv v2 HTML](https://arxiv.org/html/2606.00510v2) · [code](https://github.com/ChenChiShui/selective-skill-invocation) | Builds invoke/skip preference pairs from shared prefixes and combines episode-level outcome preference with step-level local invocation preference. It explicitly targets the local decision point; reported cross-domain tests include unseen skills. | Direct prior art for selective invocation and counterfactual invocation utility. It learns a policy from preference pairs rather than a structural invariant, but overlap covers any broad claim to state-local skill use/abstention. |
| **When Not to Imitate: Boundary-Aware Skill Memory (BASM)** (Lin et al., Findings EMNLP 2026; arXiv v1) | [arXiv HTML](https://arxiv.org/html/2608.22339) · [version](https://arxiv.org/abs/2608.22339) | Adds applicability, risk, avoidance and recovery boundary fields to trace-derived skills; conditions use/suppression/repair on boundaries. | Direct prior art for boundary-aware skill representation and boundary-conditioned execution/repair. It does not appear to learn a formal action/effect invariant boundary from independently classified replay counterexamples; verify extraction details/code before a narrow contrast. |
| **MUSE-Autoskill: Self-Evolving Agents via Skill Creation, Memory, Management, and Evaluation** (Lin et al., 2026) | [arXiv v2](https://arxiv.org/abs/2605.27366) | End-to-end skill lifecycle, creation/reuse/refinement, per-skill memory, evaluation and runtime feedback; reports transfer and cost. | Creation, validation, reuse, lifecycle or amortized-cost arguments are already occupied. Not the specific boundary-learning question. |
| **EvoClawBench: Can Agents Learn Reusable Skills from Their Own Runs?** (Peng et al., 2026) | [arXiv v1 HTML](https://arxiv.org/html/2607.09711v1) | Compares baseline, pre-authored skills and post-run self-authored skills; reports mixed effects and end-to-end authoring/reuse cost. | Strong prior art for evaluating skill creation from own runs and cost; underscores that skill authoring is not automatically helpful. It does not establish the proposed invariant-versus-replay comparison. |
| **A Framework for Evaluating Agentic Skills at Scale** (Shaposhnikov et al., 2026) | [arXiv HTML](https://arxiv.org/html/2606.17819) | Generates skill-relevant tasks and rubrics; compares with-skill/no-skill behavior across many skills/models. | Broad skill utility evaluation is already active. T2T’s contribution cannot be a generic skill evaluation framework. |
| **Skill Coverage: A Test Adequacy Metric for Agent Skills** (Tan et al., arXiv 2606.20659v2) | [arXiv v2 PDF](https://arxiv.org/pdf/2606.20659v2) | Defines skill behavior constraints with explicit applicability conditions and expected behaviors; maps execution traces to whether each applicable constraint was exercised and passed/failed, with human review of generated constraints. | Direct prior art for behavior-level skill-use auditing and applicability-conditioned trace evaluation. It is a test-adequacy metric, not an invariant learner or boundary refiner; nevertheless generic auditing/coverage is not a T2T novelty wedge. |
| **Skill Use or Skill Theater?** (Hu et al., 2026) | [arXiv HTML](https://arxiv.org/html/2607.27484) | Paired no-skill counterfactuals and semantic/content/assignment interventions estimate whether skills causally affect decisions and whether effects help or harm. | Generic interventions or audits of skill use are not novel. T2T’s matched arm is about representation/boundary contribution, not claimed-use attribution. |

## B. Direct ARC-AGI-3 overlap: predictive models, verification and counterexamples

| Work | Primary source / status | Mechanism relevant to T2T | Review implication |
|---|---|---|---|
| **Twin: Playing an Unknown Game with a Test-Time Digital Twin** (Skoutnev et al., 2026) | [arXiv HTML](https://arxiv.org/html/2608.14490) | Agent writes executable world model, validates against all observed transitions, blocks actions until replay-consistent, predicts before action, halts on mismatch and repairs from counterexamples. | Extremely close benchmark-specific overlap. It already establishes counterexample-driven repair and prediction gating for ARC-AGI-3 dynamics. T2T cannot claim those ideas, nor “first counterexample-guided model repair.” Possible distinction is persistent reusable *skill applicability* boundaries across distinct contexts, rather than repair of a per-game dynamics model; verify carefully. |
| **Tycho: Active Abstraction with Programmatic World Models for ARC-AGI-3** (Lehmann et al., 2026) | [arXiv HTML](https://arxiv.org/html/2607.28287) | Formalizes ARC-AGI-3 as parameterized rendered deterministic Moore machines; model beliefs, level boundaries, information-gathering actions, verification, planning, and selective model use. Finds prediction accuracy alone insufficient for good play. | Direct benchmark/method overlap in reusable structure, active exploration and action costs. A static skill-scope claim must separate from game-specific model induction and demonstrate cross-context value. |
| **Executable World Models for ARC-AGI-3 in the Era of Coding Agents** (Rodionov, 2026) | [arXiv v1 HTML](https://arxiv.org/html/2605.05138v1) | Maintains executable Python transition models, verifies past observations, refactors toward simpler abstractions and plans before acting. | World-model verification, refactoring and transition replay are prior art. The first-run public-set result is preliminary; it does not itself test invariant skills against strong replay. |
| **Workspace Optimization: How to Train Your Agent (DreamTeam)** (Sarafian et al., arXiv v1, 2026-05-10) | [arXiv v1 HTML](https://arxiv.org/html/2605.09650v1) | ARC-AGI-3 harness routes each confirmed/contradicted prediction to typed workspace artifacts (observation, dynamics, strategy, probing); patches are replayed against prior evidence; reusable strategies are retained when supported by simulation and evidence. | Strong benchmark-specific overlap in counterexample routing, repair, regression replay, and reusable strategy artifacts. It is not specifically an invariant-derived skill applicability learner; it makes general ARC counterexample-driven workspace/model repair and reusable strategy construction unavailable as novelty claims. Report its own two-run/public-set results only as author-reported paper results, not T2T evidence. |
| **OPINE-World: Programmatic World Modeling with Ontology-error-Prioritized Interactive Exploration** (Fox et al., 2026) | [arXiv v2](https://arxiv.org/html/2607.01531v2) | Prioritizes exploration by ontology error, verifies programmatic world models against observations, and uses counterexample-guided synthesis/repair. | Close in object/effect abstraction and counterexample-guided model revision. T2T must say how skill-level scope differs from ontology/model correction. |
| **arc-skill** (open-source project; public claims by maintainers) | [project write-up](https://arc-skill.vercel.app/) · [repository](https://github.com/pbshgthm/arc-skill) | Requires a falsifiable next-action prediction; grades it against the resulting board; halts queued plans at first mismatch; reports 25 public games and 7,627 graded predictions. | Direct prior art for predict-before-act, mismatch as evidence, action gating and ARC-AGI-3 performance. T2T’s prediction/check cannot itself be novel. Treat performance as maintainer-reported artifact result, not independent validation. |
| **Tracing the Thoughts of a Coding Agent Playing ARC-AGI-3: Lessons for Continual Learning** (Wu et al., 2026) | [arXiv v1 HTML](https://arxiv.org/html/2610.11450) | Measures script/reference reuse, copying, rewriting and abandonment across level boundaries; reports sparse cross-level references and frequent script rewrites/abandonment. | Direct empirical prior art for ARC-AGI-3 knowledge persistence and cross-level transfer failure modes. It measures artifact behavior, not a counterexample-guided invariant learner. |
| **Schema: Discovering Unknown Environments via Agentic Program Induction** (Zeng et al., 2026) | [project site](https://schema-harness.github.io/) · [arXiv reference](https://arxiv.org/abs/2609.39140) | Uses persistent world models, active information-gathering, backtests and predictions; reports public ARC-AGI-3 results and action-by-action artifacts. | Close, fast-moving ARC prior art; must compare exact model, counterexample and transfer handling from the paper/repo before final claims. Project-site claims are author-reported. |

## C. Foundational conceptual antecedents and adjacent ARC search/ranking work

| Work | Primary source | Mechanism | Review implication |
|---|---|---|---|
| **Boosting Performance on ARC is a Matter of Perspective** (Franzen et al., 2025) | [arXiv v1](https://arxiv.org/html/2505.07859v1) | Generates diverse high-probability candidate solutions with search and uses product-of-experts scoring to select/rank candidates. | Candidate generation/coverage and selection/ranking are already distinct, explored mechanisms in ARC. Broad “generate/support candidates before ranking” framing is not novel. Adjacent, not direct, to AGI-3 skill boundaries. |
| **Options framework** (Sutton, Precup & Singh, 1999) | [DOI](https://doi.org/10.1016/S0004-3702(99)00052-1) | Temporally extended actions defined by initiation set, internal policy and termination. | Applicability sets and termination conditions for skills are longstanding. A new contribution must be a learning/evaluation mechanism, not a schema containing preconditions. |
| **Skill Transfer for Temporally-Extended Task Specifications (LTL-Transfer)** | [paper PDF](https://jasonxyliu.github.io/paper/ltl-transfer_22.pdf) | Learns portable transition-centric options with preconditions/constraints/effects and transfers them to unseen temporal task specifications. | Transition-centric portable options with conditions/effects predate this project. Distinguish transfer setting and counterexample-update process. |
| **Skill acquisition via transfer learning and advice taking** (Torrey et al.) | [paper PDF](https://www.d.umn.edu/~rmaclin/publications/torrey-ecml2006.pdf) | Learns logical state conditions for action advice from source-task experience and transfers to related target tasks. | Explicit relational conditions on transferable behavior are not new. |
| **DreamCoder: Bootstrapping Inductive Program Synthesis with Wake-Sleep Library Learning** (Ellis et al., PLDI 2021) | [DOI](https://doi.org/10.1145/3453483.3454080) · [supplementary PDF](https://www.cs.cornell.edu/~ellisk/documents/dreamcoder_with_supplement.pdf) | Learns reusable abstractions/library functions by compressing/refactoring programs that solve multiple tasks, paired with learned search. | Cross-task abstraction from successful procedures and compression are established. Distinguish semantic invariant scope learning from general library discovery. |
| **Counterexample-Guided Abstraction Refinement (CEGAR)** (Clarke et al., CAV 2000; later work) | [CAV 2000 DOI](https://doi.org/10.1007/10722167_15) · [2004 journal paper](https://doi.org/10.1109/TCAD.2004.829807) | Checks whether an abstract counterexample is real; refines abstraction using real counterexamples; repeats until verification/refutation. | Counterexample-guided refinement is established. T2T needs a distinct object, learning objective, data regime and demonstrated transfer contribution; terminology alone is insufficient. |
| **Transfer in Reinforcement Learning via Shared Features** (Konidaris et al., 2012) | [JMLR](https://www.jmlr.org/papers/v13/konidaris12a.html) | Learns portable representations/features and transfers options/policies across tasks with distinct states. | Invariant/shared-feature transfer has longstanding RL literature. |

## Source quality / limits

arXiv, ACL Anthology, DOI/JMLR and author project pages were preferred. Author-maintained claims are marked as such; search-index snippets are not promoted to verified primary-source evidence. The finite #6645 fixture/PR outputs are described only as self-reported method-construction evidence, not scientific or ARC results. Several sources are recent preprints or new proceedings publications; version, peer-review status and artifacts should be rechecked at submission time. This inventory is not an exhaustive systematic review or a legal/patent opinion.
