# T2T-S1.3 — Boundary-Learning Measurability Check

**ID:** `T2T-S1.3-BoundaryMeasure-v1.0.0-draft`  
**Method:** analytically constructed, deterministic synthetic key/door micro-world; no code was written or run.  
**Question:** can a counterexample change an observable applicability boundary, and can the change be evaluated on data not used to make it?

## Toy world definition

An agent is adjacent to a closed door and may take action `USE_KEY_AND_ENTER`. A key and door each have an observable color; `has_key`, `adjacent`, `door_closed`, and `corridor_clear` are also observable.

The world has a deterministic transition rule:

`Applicable(s) = adjacent AND door_closed AND has_key AND corridor_clear AND (key_color == door_color)`

If applicable, `USE_KEY_AND_ENTER` opens the door and advances the agent. Otherwise it has no successful open-and-enter effect. The effect comparator is exact equality on `{door_open, agent_advanced}`. Unknown/unobserved required fields would yield UNKNOWN/abstain, not FALSE.

The candidate predicts the successful effect. Its initial guard deliberately omits the final color-match predicate:

`G0 = adjacent AND door_closed AND has_key AND corridor_clear`

The only proposed refinement is:

`G1 = G0 AND (key_color == door_color)`

The equality predicate is assumed to belong to a prospectively pinned, observable predicate vocabulary. If the representation cannot observe or compare the two colors, this fixture is blocked rather than rescued with hidden state.

## Evidence separation

- A **source support** context establishes one successful instance.
- A separate **scope counterexample** is available for refining a successor from `G0` to `G1`.
- That counterexample is not used to evaluate the successor. The validation rows below are fresh contexts and are evaluated only after the guard is frozen.

The table is a designed truth-table, not data produced by a learner:

| Row | Role | Adjacent / closed / key / clear | Key → door color | True applicability | `G0` | `G1` | Actual effect |
|---|---|---|---|---:|---:|---:|---|
| S+ | Source support | yes / yes / yes / yes | blue → blue | yes | admit | admit | opens + advances |
| CE | Refinement-only counterexample | yes / yes / yes / yes | red → blue | no | **admit (false activation)** | reject | no successful effect |
| H1 | Fresh validation | yes / yes / yes / yes | green → green | yes | admit | admit | opens + advances |
| H2 | Fresh validation | yes / yes / yes / yes | yellow → yellow | yes | admit | admit | opens + advances |
| H3 | Fresh validation | yes / yes / yes / yes | violet → orange | no | **admit (false activation)** | reject | no successful effect |
| H4 | Fresh validation | yes / yes / yes / yes | red → blue | no | **admit (false activation)** | reject | no successful effect |
| H5 | Fresh validation | yes / yes / no / yes | blue → blue | no | reject | reject | no successful effect |
| H6 | Fresh validation | yes / yes / yes / no | blue → blue | no | reject | reject | no successful effect |

## Observable measures

On the six **fresh validation** rows H1–H6, report measures separately:

| Measure | `G0` | `G1` | Interpretation |
|---|---:|---:|---|
| False activations among 4 truly non-applicable contexts | 2/4 | 0/4 | The refined boundary rejects the two color-mismatch cases. |
| False-activation rate among all admitted contexts | 2/4 | 0/2 | The refined guard improves precision in this finite fixture. |
| True applicable contexts admitted | 2/2 | 2/2 | No positive-context coverage is lost in these rows. |
| False rejections among applicable contexts | 0/2 | 0/2 | Neither version rejects the two valid contexts. |
| Coverage (admitted / 6 validation contexts) | 4/6 | 2/6 | Reported separately; lower total activation is not, by itself, boundary improvement. |

For this deterministic finite fixture, the **toy B criterion** is: `G1` must strictly reduce false activations on fresh validation contexts while admitting every applicable validation context admitted by `G0`. It passes in the constructed table. This criterion does not use the CE row as validation, does not optimize a composite, and is not a stochastic-study threshold.

## Feasibility conclusion

**The mechanism is observable and measurable in principle in this toy world.** The counterexample changes a concrete predicate in an immutable successor guard; subsequent fresh contexts permit separate measurement of false activation, false rejection, and coverage. The truth labels are generated by a fully specified transition rule, so the comparison does not depend on ARC outcomes or subjective task success.

This is a **constructive measurability demonstration only**. It does not establish that an algorithm can infer `key_color == door_color`, that the candidate-generation process is sound, that the refined boundary generalizes beyond this tiny domain, or that counterexamples reduce negative transfer/harm. The result is true by construction and has no population uncertainty.

## Critical strong-replay caveat

A sufficiently expressive parameterized replay or short script can encode the same color equality and match `G1`. Therefore the example demonstrates **B measurability**, not Claim N. It also exposes a necessary stress test: if the “invariant” is just a compact relational guard that a fair replay compiler can produce under the same source/cost budget, no invariant-specific increment has been shown. See the [strong replay specification](strong_replay_spec.md).

## What this fixture does not settle

- The accuracy/abstention metric for Claim N is separately defined in `claim_N_decision_rule.md`.
- Whether real observations expose the required state variables without leakage or ambiguity.
- How noisy or conflicting outcomes are adjudicated; the fixture is deterministic.
- Whether multiple predicates, stochastic effects, hidden state, or incomplete observations make the boundary non-identifiable.
- Harm reduction, task score, cost-effectiveness, ARC transfer, or novelty.
