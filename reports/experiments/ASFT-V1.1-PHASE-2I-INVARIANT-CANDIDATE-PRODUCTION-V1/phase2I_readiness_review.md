## Executive finding

The next scientific question is upstream: can a frozen ARC pipeline generate accepted invariant candidates at all? Phase 2I keeps the Phase 1C ranked object fixed and specifies a development-only comparison of current R1 against Phase 2F's object-centric R3 under the same downstream miner, support policy, trace contract, and candidate definition.

However, Phase 2I cannot honestly claim to have produced candidates: R3 is not implemented, independent task-family annotations do not exist, and a common semantic trace adapter is unresolved. The Phase 2H baseline remains zero accepted candidates. Therefore this package is a **candidate-production program specification**, not a candidate-production result. It does not authorize running an improvised representation or lowering thresholds.
