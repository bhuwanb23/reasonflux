## Executive finding

Phase 2H answers the upstream question: **what exact objects should IDT rank, and can the current ARC pipeline produce them in nonzero quantity?** For the Phase 1C RQ1 design, the target is an outcome-blind invariant candidate (`Invariant`) emitted by the trace-mining candidate-generation stage. The audited ARC path has **zero accepted candidates**. The only nonzero pre-eligibility objects are raw traces/fragments, generic patterns/structures, and rejected proposals; none is an approved substitute.

The present blockage is therefore upstream of pressure, FNTU, power, and calibration. A benchmark engine can rank synthetic cards, but the audited actual ARC pipeline does not supply a qualified population for that benchmark. This is an availability/readiness finding, not IDT efficacy evidence and not universal falsification.

## Eligibility and design guardrails

A future RQ1 candidate registry should contain only source-lineaged, canonicalized invariant candidates generated from pre-outcome discovery/calibration material. It must separate generation, structural eligibility, transfer verification, and later skill promotion. It must not condition entry on future value or positive held-out transfer; observed calibration T=0 may remain eligible, while no eligible opportunities is unavailable. Exact numerical thresholds and the identity/dedup rule must be frozen in one hash-pinned config before a new generation run.

Do not relabel generic control-flow patterns, source solver programs, or skills as invariants to make the denominator nonzero. If leadership changes the ranked object, issue an explicit F3 benchmark redesign before feature computation or outcome access.
