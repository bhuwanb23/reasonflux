# Phase 3A-R — Independent FNTU Evaluator Validation

**Gate 4 status: BLOCKED.** The current workspace has FNTU arithmetic, not an independent task-based endpoint.

## Existing arithmetic contract

The Phase 3A development engine implements:

`FNTU@K = [Σ_t (U(S,t) − U(∅,t)) − λ C(S)] / (K×H)`.

It requires R1–R5 paired rows, same task IDs/horizon, common no-candidate baseline, exactly K selections, fixed portfolio cost, and a frozen hashed cost-model identifier. It rejects rank scores as endpoint inputs. Contract fixtures can return a loss, tie, or win. This confirms the arithmetic interface only.

## Required E1–E6 components

| Component | Current status | Evidence gap |
|---|---|---|
| E1 Utility evaluator | **MISSING** | No Phase 1C task runner evaluates selected invariant portfolios on actual future tasks using a frozen correctness/quality utility map. |
| E2 Cost evaluator | **MISSING** | No portfolio creation/storage/maintenance/compute cost measurements or locked cost components for this RQ1 benchmark. |
| E3 λ conversion | **MISSING** | No calibration-derived, validated λ on common units. A numeric fixture value is not calibration. |
| E4 Task horizon H | **MISSING** | No frozen number/mix of eligible future opportunities or cross-family blocks. |
| E5 Paired baseline | **ARITHMETIC ONLY** | Code enforces a shared no-candidate utility value per task; no independently executed counterfactual baseline exists. |
| E6 Missingness policy | **INCOMPLETE** | Phase 1C gives >5% and >2pp unavailability thresholds but lacks an estimator for below-threshold missing rows; Phase 3A conservatively rejects any missing row. The final rule is not frozen. |

## Independence and provenance checks

- FNTU's interface is separate from score calculation, so arithmetic need not depend on R1 internals.
- Task execution, utility labels, cost conversion, task/family assignment, and outcome snapshots are not generated by an independent evaluator.
- The 13D synthetic transfer task rows use a different task/utility definition and analysis protocol. They are not FNTU validation data and cannot supply variance or λ for the RQ1 endpoint.
- Historical Phase 13B TU is also not a substitute for the Phase 1C FNTU estimand.

## Decision

No independent FNTU endpoint exists to validate. Before Gate 4 can pass, implement and hash an evaluator independent of candidate scores; freeze correctness/quality utility, paired baseline, cost units/components, λ, K and H; define NOT_APPLICABLE/FAILED/MISSING; settle below-threshold missing-data aggregation; and pass tests on real task executions without using confirmatory outcomes. No endpoint outcomes or power parameters are inferred here.
